# ADR-004: Versioned catalog families for PIM

- **Status:** Accepted for the isolated lab (v1); not yet used for production data.
- **Date:** 2026-11-17
- **Decision owners:** AgeStyles project
- **Upstream versions:** Medusa 2.22.3, Mercur 2.4.1, `@medusajs/framework` 2.22.3.

## Context

`Agestyles-Catalogo` stores a `CatalogFamily` per category (`category_slug`) with an embedded `fields[]` definition and a `version`. Products point at a family version, and the comparison page only compares products of the same version. Mercur 2.4.1 already provides a typed attribute dictionary (`product-attribute` + `product-attribute-value`) with required/filterable/variant-axis flags and category links, but it has no notion of a versioned family or of presentation metadata such as `comparable`, `group`, `help` or frozen units.

Rebuilding the dictionary inside AgeStyles would duplicate Mercur and break the supported extension path. Reusing only Mercur would lose the version semantics that make comparisons correct.

## Decisions

1. **Owned module, no core fork.** Families and versions live in `@agestyles/catalog-pim`, a standard Medusa module registered in `apps/commerce-api/medusa-config.ts`. It uses `MedusaService`, model definitions, generated migrations, and the framework's automatic `/admin` user authentication and `/store` publishable-key guard. No file under `@mercurjs/*` or `@medusajs/*` is modified.
2. **Category reference is `product_category.id`.** `CatalogFamily.category_id` stores the Medusa category id, not the legacy `category_slug`. Ids survive category handle renames; the ETL resolves `category_slug` → category `handle` → id once. The admin create route rejects unknown ids before writing.
3. **Versioned, frozen field snapshots.** `CatalogFamilyVersion` stores `fields` as JSONB. Publishing validates the snapshot, sets `frozen_at`, publishes the version and archives the previously published one. Editing creates a new draft version; published versions and their products are never mutated. Only one draft per family exists at a time.
4. **The dictionary stays in Mercur.** A field stores `attribute_handle` (and optionally `option_handles`) referencing `ProductAttribute`/`ProductAttributeValue` handles. Labels, units and bounds are frozen on the version so a later dictionary edit cannot silently change an existing comparison. Field types map onto Mercur's enum:
   - `text` → `text`
   - `number` → `unit` (numeric; unit symbol optional)
   - `boolean` → `toggle`
   - `select` → `single_select`
   - `multiselect` → `multi_select`
5. **Writes are platform-owned.** Only administrators define families and publish versions; sellers fill values. `/admin/catalog-families*` inherits Medusa's `authenticate("user", ["bearer", "session", "api-key"])` middleware from the `/admin` prefix. The public `/store/catalog-families/:handle` endpoint returns only the published version and only for active families, so drafts never leak.
6. **Comparison is version-scoped.** `compareCatalogProducts` lives in `@agestyles/domain/catalog-pim` and requires 2–4 products with the same `catalog_family_version_id`; missing families and different versions are reported separately. It excludes `comparable: false` fields and matches keys case-insensitively.
7. **Product association (next increment).** Products will carry `catalog_family_version_id` and will be validated against a published version. v1 fixes the comparison input contract; persistence will use supported product metadata without a core change unless a reporting need forces a Medusa link.

## Consequences

- Families can evolve without invalidating products already published against an older version.
- The PIM does not duplicate Mercur attributes or values; the ETL must map legacy attribute codes and option ids to Mercur handles.
- Category reporting joins through `product_category.id`; a readable handle requires resolving the category.
- Admin UI, vendor read endpoints and the product→version assignment remain to be built on these contracts.
- The migration was generated by `medusa db:generate agestylesCatalogPim`; no SQL was written by hand.
